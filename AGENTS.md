# Repository work

Read [CONTRIBUTING.md](CONTRIBUTING.md) before changing this repository. It defines the documentation, verification, licensing, and contributor-credit requirements for every PR.

## Find the relevant guidance

- For firmware or hardware work, read [development](docs/development.md), [porting](docs/porting.md), and [hardware verification](docs/hardware-validation.md). Use the project's configured ESP-IDF APIs and the board checklist in CONTRIBUTING.md.
- For CLI, simulator, plugin, or Linux behavior, read the corresponding user guide and existing tests before changing the interface. The contribution guide maps change types to documentation and verification.
- For website or guide changes, inspect `site/package.json` for commands and `site/scripts/docs.mjs` for published pages. A new guide needs working navigation, search, and links.
- For vendor-derived code or register data, follow the licensing section in CONTRIBUTING.md and inspect `NOTICE` and `THIRD_PARTY_NOTICES.md` before adding material.

## Complete the change

1. Inspect the working tree and preserve unrelated user changes. Keep the implementation scoped to the requested behavior.
2. Update the affected documentation in the same PR, or explain why no documentation changes apply.
3. Run the relevant checks from [development](docs/development.md). For a bug fix, verify the observable failure and corrected result where practical. Do not weaken assertions to make a failure disappear.
4. Review the final diff for unintended changes, missing notices, and stale instructions.
5. Report what changed, the checks run, their results, and any remaining limitations. Distinguish hardware measurements, simulations, test doubles, and untested assumptions.

Keep contributor authorship and credit when fixing or salvaging another person's work. Merge only when authorized and the current PR revision passes CI. Do not describe an experimental hardware port as verified without the required physical report.

## Android Live voice gotchas

- Free-text Hermes `clarify` requests differ from yes/no approvals. The gadget currently shows the base numbered-text fallback without a dedicated reply card; an unresolved clarification keeps Hermes busy. In the issue #8 test, the ordinary request lost its hostname clause and asked what to do after waiting. The read-only test continued after `am start -W ... --es console "'say Report the hostname'"` supplied its intended answer. Do not mistake busy admission for a call failure or reset the conversation to clear it.
- Live wake activation now follows the saved phone Voice mode; Hermes voice remains the default. To select Live over ADB, use `am start -W ... --es voice_mode live` and let the command finish before another activity launch; back-to-back launches can race and leave the old mode selected. Confirm the choice on the settings screen before qualifying wake-to-call.
- Start the 500 ms rearm tail from the clock after media/cue close, not from the coordinator's last tick: WebRTC teardown can block and otherwise consume the tail.
- The call controller consumes voice-service data-channel JSON. `input_transcript.added` and `output_transcript.added` contain deltas in `item.text`; retain whitespace deltas. `turn.done` can be partial or absent. Spoken hang-up matches only the complete user utterance after a 3.5 s quiet gap, never assistant output or a substring. Idle timing uses recognized speech from both roles and pauses for unresolved requests and observed Hermes turns across calls; only a matching terminal receipt or `turn.end` releases a turn and starts a fresh 60 s window. Missed completion while disconnected conservatively leaves automatic idle hang-up paused; explicit End call still works. Do not infer acoustic silence or reliable transcription from those timers.

- Read the OnePlus 8T echo and interruption report in `docs/hardware-validation.md` before changing the call audio path. On that phone, WebRTC uses the platform echo canceller and noise suppressor and disables its software equivalents. The ready cue plays outside WebRTC; its rejection depends on the platform echo canceller.
- Spoken interruption is handled by the voice service. The phone has no gateway interrupt route, and `/codexlive/interrupt` does not stop speech on codex-cli 0.160.0. Preserve independent phone and desktop calls when adding handoffs.
- The service sometimes loses words spoken over playback or at the start of a call. Seven measured interruptions stopped playback after 0.7–2.8 seconds, but two needed repetition. Do not infer reliable transcription from successful interruption.
- WebRTC's `media-source.audioLevel` stayed zero on the 8T. Use captured PCM levels for diagnostics, and keep audio and transcript content out of committed logging. Measurements from temporary instrumentation are separate from host tests with scripted media.
- Update the configured phone with `adb install -r` using its existing debug signing key. Do not uninstall it or run `connectedAndroidTest`; that loses gadget identity and device-owner setup. Wireless ADB ports change; the last tested endpoint was `10.0.10.156:39859`, which closed with the issue #9 reboot. Wireless ADB is separate from the gadget URL `ws://10.0.10.3:8765/gadget`.
- Live tasks travel from `WebRtcCallMedia`'s native `delegation.created` through `LiveCall` as `call.task`. `call.task.status` binds call id, delegation id and the actual Hermes message/turn id. Resolve the native item only on a terminal receipt, once; duplicate events and ambiguous transport failures must not resubmit work. Hosts advertise `welcome.call_tasks` separately from calls.
- The adapter owns accepted task tracking, not `DeviceCalls.end_device`. Hang-up, disconnect and Microphone off must leave accepted work running and retain its slot until `on_processing_complete`. Keep both streaming and file gadget TTS suppressed for that task, including after hang-up. Only the still-authorized originating call may receive its result; a new call gets busy feedback while old work remains active.
- Match processing completion to the exact Hermes turn before removing tracking or emitting `turn.end`. Duplicate or stale completion callbacks must not release a newer task's slot.
- The phone can show Responding and then Ready for an interim reply while a terminal task is still running. Use stored terminal results and the final answer to qualify completion; `android/tools/live_task_lifecycle.py` does this on the paired host. Text arriving on the screen after Microphone off is expected; it does not establish audible playback.
- For actual gadget speech, inspect Android's active playback configurations for `USAGE_ASSISTANT`. `AudioStatus.GADGET_PLAYBACK` also includes the intentional 500 ms re-arm tail, and Microphone off takes priority over speaker state. The issue #7 report in `docs/hardware-validation.md` separates spoken checks from scripted delegations and a scripted media-failure callback; those scripted checks do not establish native audible busy feedback or behavior during an external network outage.
- Task slots and voice receipts are process-local. Reconnecting the same device key preserves admission while the gateway runs, but gateway restart does not provide durable task recovery, and missed voice results are not replayed. Keep uncertain requests from being resubmitted.
- Submit Live delegations as TEXT with `allow_gateway_control=False` to the existing device DM in the adapter's profile. VOICE would select `auxiliary.voice_chat`. Admission checks Hermes's `_event_session_key` / `_active_sessions` guard before dispatch and uses `_gateway_accepted`; these private contracts are listed in `plugin/compat.py` and need real-gateway regression coverage when Hermes changes.
- The Live Voice public `start_call` API now has the phone's conversation policy; dashboard routes keep their desktop queue/wait policy. Stories and small talk belong to the voice, and casual conversation remains available during tasks. Keep execution restrictions in the broker and approvals on-screen; prompt wording alone is not an execution restriction.
- SDK voice work targets fork branch `android/client`, not upstream `main`. The configured gateway uses a plain plugin copy in `~/.hermes/plugins/gadget`; deploy SDK Python changes there and restart `hermes-agent`. The Live Voice install is a separate checkout. Use the packaged Hermes Python and locales for host checks; `HERMES_GADGET_TEST_PYTHON` supports that runtime in gateway E2E, and `HERMES_LIVE_VOICE_DIR` must name the broker checkout with its fake app-server. See `docs/development.md` and the issue #6 hardware report for commands and measured limits.

## 8T deployment and test-harness gotchas

- The phone's Tailscale VPN is `bypassable=false`. Keep WebRTC's network monitor disabled in `WebRtcCallMedia`. With it enabled, WebRTC binds sockets to Wi-Fi, Android refuses that under the VPN, and every Tailscale call fails after the SDP answer. Changing it needs a real call over Tailscale on the phone; host tests can't check it.
- With the phone's Tailscale up, the LAN URL is routed through the `pi` node (`10.0.10.4`), which advertises `10.0.10.0/24`. Use `ws://zaza.taila757c4.ts.net:8765/gadget` for Tailscale runs. Turn it on and off with `am broadcast -a com.tailscale.ipn.CONNECT_VPN|DISCONNECT_VPN -n com.tailscale.ipn/.IPNReceiver`. The phone's normal setup is LAN with Tailscale off.
- `AdbSetup --es server` without `--es name` resets the name to the default. Always pass `--es name 8T`.
- `am instrument` kills the app when it finishes, which leaves the phone offline and unpinned. Relaunch with `am start -W -a android.intent.action.MAIN -c android.intent.category.HOME`; the companion scripts do this. `am force-stop` does not kill the device-owner app. Use `run-as io.github.adolanium.hermesgadget kill -9 <pid>`, after which Android restarts the service.
- The 8T's echo canceller removes the phone's own media playback from a Live call. Loudspeaker prompts (`android/tools/live_acoustic.py`) can test wake, hold-to-talk, readiness, idle expiry and re-arming, but not in-call speech, interruption or "Goodbye Hermes". Zaza has no usable audio output (the `hermes` user isn't in `audio`), so in-call speech needs a person.
- Scripted `delegation.created` ids aren't the service's items. Its `delegation.context.append` for them produces an `error` event, and the voice never reads the result. Scripted tasks test admission and lifetime only.
- `adb reboot` turns wireless debugging off. adb here has no mDNS discovery, and nothing listens until the owner turns it back on (settings screen → **Open Android settings**). Reboot last, and check the reconnect in `agent.log`.
- For desktop-side overlap tests, start a second `hermes dashboard --host 127.0.0.1 --port 9139 --no-open --skip-build` with the `hermes-backend` environment plus your own `HERMES_DASHBOARD_SESSION_TOKEN`. Then drive `/api/plugins/talk-desktop/codexlive/session|stop` with the `Client` from `hermes-live-voice/tools/live_call_check.py` (`/tmp/lv-venv` has aiortc). Kill the listening PID afterwards. `kill -STOP` on that dashboard's own `codex app-server` child produces `LIVE_TIMEOUT` after 25 s.
- Use `uv run --no-project` in this repo; plain `uv run` writes a `uv.lock` into the root.
